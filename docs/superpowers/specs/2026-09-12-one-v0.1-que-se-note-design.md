# ONE v0.1 "que se note": diseño (aprobado por Carlos el 12-sep-2026)

Origen: brainstorming del 12-sep (`docs/2026-09-12-brainstorming-gamificacion.md`). Carlos eligió las 6 recomendadas y fijó en la revisión: **no sobrecomplicar**; **selector de confianza Baja/Media/Alta en lugar de IDK** (uno u otro, no los dos), simple e intuitivo; **repaso final con swipe**; **cada pantalla cabe entera, sin scroll ni rebote** (hub compacto 4×2, feedback debajo de la tarjeta pero compacto, no panel flotante); **racha 🔥 se mantiene tal cual y no hay cinta de sellos**; Baja + acierto **cuenta pero no consolida**.

Objetivo: que al abrir ONE se note que el sistema recuerda lo que hiciste y que cada fallo tiene un camino de vuelta. Sin servidor, sin tocar el pipeline. Estética y tono actuales (oscuro + cian, sobrio, sin magenta).

## 0. Principios de implementación

- Motor puro en `motor.js` (sin DOM), UI en `app.js`/`index.html`/`estilos.css`. Tests del motor con `node --test tests/*.test.js`, e2e Playwright 375×812 con `data-test` (`locator('[data-test="…"]')`).
- Estado `version` 1 → 2. `normalizarEstado` rellena los campos nuevos con valores por defecto para estados v1 (importar un JSON viejo nunca rompe; los tests lo cubren con un estado v1 real).
- Ningún paso obligatorio nuevo para responder: la confianza tiene un valor por defecto (Media) y solo se toca si se quiere.
- Rutas relativas (GitHub Pages en subcarpeta). Subir `CACHE` en `sw.js` a `one-v4`.

## 1. Datos nuevos en el estado

```js
// crearEstado(hoy) devuelve además:
recuperadas: 0,                              // total histórico de recuperaciones
confianza: { altas: 0, altasOk: 0, bajas: 0, bajasOk: 0 },
mision: null,                                // { fecha, ids: [..hasta 3], hechas: [ids], completada: bool }

// cada tarjeta (estado.tarjetas[id]) añade:
ultimo: 'AAAA-MM-DD',       // última vez respondida
ultimoFallo: 'AAAA-MM-DD' | null,
pendiente: bool,            // true tras fallo; false tras acierto
prioridad: 0 | 1 | 2,       // 2 = falló con confianza Alta; 1 = fallo normal; 0 = no pendiente
recuperada: bool,           // true al acertar una pendiente; vuelve a false si se falla otra vez
fragil: bool                // true tras acertar con confianza Baja (cuenta pero no consolida)
```

`areas[a].noLoSe` se mantiene por compatibilidad pero deja de crecer (ya no hay IDK). El historial guarda además `confianza`.

## 2. Motor: `registrarRespuesta(estado, pregunta, correcta, hoy, opciones)`

`opciones = { confianza: 'baja' | 'media' | 'alta' }` (por defecto `'media'`; `noLoSe` se sigue aceptando por compatibilidad y equivale a `confianza: 'baja'` con `correcta = false`). Reglas:

1. Escalera, combo, nivel de área, historial e `hoy`: igual que ahora.
2. **Leitner**: acierto sube de caja **salvo** con confianza Baja (`fragil = true`, la caja no cambia y `proximo = hoy + INTERVALOS[caja]` se recalcula igual). Acierto con Media/Alta: `fragil = false`. Fallo: caja 0 como ahora.
3. **XP**: acierto con Alta multiplica por 1,5 el XP ya calculado (tras el combo), redondeado. Baja y Media: XP normal. Fallo: 0.
4. **Confianza (contadores)**: Alta → `confianza.altas += 1` y `altasOk += 1` si acierta. Baja → `bajas += 1` y `bajasOk += 1` si acierta.
5. **Pendiente**: fallo → `pendiente = true`, `prioridad = max(prioridad, alta ? 2 : 1)`, `ultimoFallo = hoy`, `recuperada = false`. Acierto → `pendiente = false`, `prioridad = 0`.
6. **Recuperada**: acierto sobre una tarjeta que tenía `pendiente === true` antes de esta respuesta → `recuperada = true`, `estado.recuperadas += 1`, `delta.recuperada = { fechaFallo }` (el `ultimoFallo` anterior). Si no, `delta.recuperada = null`. Con confianza Baja también cuenta como recuperada (pero queda `fragil`).
7. `ultimo = hoy` siempre.
8. **Misión**: si `estado.mision` existe, `mision.fecha === hoy`, `pregunta.id ∈ mision.ids` y no está en `hechas` → se añade (acierte o no). Si `hechas.length === ids.length` y no estaba completada → `completada = true`, `delta.misionCompletada = true`.

`delta` añade: `confianza`, `fragil`, `recuperada`, `misionCompletada`.

## 4. UI

### Sin scroll ni rebote (regla general)

- Cada vista cabe en 375×812 con el banco de ejemplo y con el banco real: el e2e comprueba en hub, pregunta (las 4 mecánicas) y resumen que `vista.scrollHeight <= vista.clientHeight + 2`.
- Tipografía fluida con `clamp()` en enunciado y opciones; el enunciado tiene `max-height` con recorte elegante (`-webkit-line-clamp: 5`) y se expande al tocar si estaba recortado.
- Se mantienen `body { position: fixed }`, `overscroll-behavior: contain` en `.vista` y `100dvh`.

### Hub (`data-vista="progreso"`), compacto, de arriba abajo

1. **Radar** 150 px (`data-test="radar"`): contorno cian = `puntuacion` (como ahora); relleno más opaco = `solidez` (`data-test="radar-solido"`, no se dibuja si todas las solidez son 0). Etiquetas: emoji por área.
2. **KPIs** en una fila: 🔥 racha · Hoy a/r · Recuperadas N (`data-test="recuperadas"`) · Confianza X % (`data-test="calibracion"`, solo si `calibracion !== null`). Se elimina el chip "No sé".
3. **Fila de dos tarjetas**: **Misión de hoy** (`data-test="mision"`): "Misión de hoy · Filosofía y Arte · 1/3", tocable → partida `{ ids: mision.ids no hechas }`; completada → "Misión de hoy ✓", no tocable. **Pendientes** (`data-test="pendientes"`): "Pendientes · 7", tocable → partida `{ ids: primeras 5 de pendientes() }`; si 0 → "Pendientes · 0" atenuada, no tocable. Ambas con `aria-disabled` cuando no son tocables.
4. **Áreas**: rejilla 4×2 de baldosas (`data-test="practicar-<area>"`): emoji, nota grande (S+/S/A/B/C/D/—, `data-test="nota-<area>"`), barra fina de `puntuacion`, y debajo en 11 px "S N · R M" (`data-test="solido-<area>"`, sólidas y recientes). Sin "Nv" ni "estables". Alto de baldosa ≥ 64 px (zona táctil).
5. **Comenzar** (`data-test="comenzar"`) anclado abajo (`margin-top: auto`), y el pie Exportar/Importar como dos enlaces discretos en una línea bajo Comenzar (o dentro de un "···" si no cabe; preferir la línea).

Al entrar al hub se llama a `misionDelDia` (crea la de hoy si hace falta) y se guarda el estado. La cabecera de partida (`data-test="modo-area"`) dice "Misión de hoy" o "Pendientes" en esos modos.

### Partida

- **Selector de confianza** (`data-test="confianza"`): control segmentado de 3 bajo la tarjeta, ancho completo, alto 44 px: "Baja · Media · Alta"; Media seleccionada por defecto (`aria-pressed`), un toque cambia, se reinicia a Media en cada pregunta. Selección visible pero sobria: segmento activo con relleno cian y texto oscuro. Subselectores `data-test="confianza-baja|media|alta"`. Desaparece al responder. **Se elimina el botón IDK** (`data-test="no-lo-se"`) y su CSS.
- **Feedback compacto debajo de la tarjeta**: una sola línea de resultado "✓ +13 XP" o "✗" (con "· confianza alta ×1,5" si aplica), chips en una fila (`Recuperada · la fallaste el 9 sep` `data-test="recuperada"`; `Estabas seguro → Pendientes` `data-test="confianza-alta-fallo"`; `Misión completada` `data-test="mision-completada"`; `Frágil: volverá pronto` `data-test="fragil"` en Baja + acierto), explicación en 14 px con `max-height` y scroll interno propio si no cabe, fila "? · esta pregunta está mal" y "Siguiente". Tipografías y márgenes menores que ahora para que la vista no haga scroll con ninguna mecánica.
- Avance automático tras acierto (1,4 s) igual que ahora; con chips de Recuperada o Misión completada el tiempo sube a 2,2 s para que se lean.

### Resumen con repaso (swipe)

- Bajo las líneas actuales, bloque "Para repasar" (`data-test="repaso"`): carrusel horizontal con `scroll-snap-type: x mandatory`, una tarjeta por pregunta **fallada o respondida con confianza Baja** de la partida, en orden de aparición. Cada tarjeta: enunciado (recortado a 3 líneas), respuesta correcta en cian, explicación (13 px), y una marca "✗" o "✓ frágil". Puntos indicadores debajo (`data-test="repaso-puntos"`). Si no hay nada: "Sin fallos. Nada que repasar." (`data-test="repaso-vacio"`).
- Respuesta correcta como texto: vf → "Verdadero"/"Falso"; test4 → texto de la opción; ordenar → items en orden con " → "; error → título de la fila sospechosa.
- El resumen entero cabe sin scroll: el carrusel ocupa el espacio restante (flex: 1) y las tarjetas hacen scroll interno si la explicación es larga.

## 5. Lo que NO entra

- Cinta de sellos y cualquier sustituto de la racha (Carlos: solo la racha, sin cinta).
- Panel/bottom-sheet de feedback (Carlos: debajo, más compacto).
- Penalizar XP por fallar con Alta: el castigo es perder el combo y entrar en Pendientes con prioridad.
- Deslizador continuo de confianza: tres segmentos.

## 6. Pruebas

Motor (`tests/motor.test.js`, mantener los 79 en verde): Alta ×1,5 y contadores; Baja + acierto no sube caja y marca `fragil`; Baja + fallo cuenta en `bajas`; pendiente/prioridad/recuperada en las transiciones (fallo→acierto, Alta+fallo→prioridad 2, acierto→fallo→acierto cuenta 2 recuperaciones); `pendientes()` orden; `misionDelDia` idempotente el mismo día, cambia de día, elige áreas flojas, tolera banco pequeño; `resumenProgreso` con `hoy` (recientes, solidez, calibracion null si altas < 5); filtro `{ ids }` termina al agotarse; `normalizarEstado` sobre un estado v1 real (sin `confianza`, sin campos de tarjeta nuevos).

E2E (`tests/e2e.spec.js`, banco de ejemplo): hub muestra Misión de hoy y Pendientes · 0; selector de confianza visible antes de responder y ausente después; Alta + acierto muestra "×1,5"; fallo → hub muestra Pendientes · 1; partida de Pendientes → acierto muestra chip Recuperada y Pendientes vuelve a 0; resumen con "Para repasar" (carrusel con ≥1 tarjeta) tras un fallo y con "Sin fallos" cuando no; **ninguna vista hace scroll** (aserción de `scrollHeight`). Capturas: `02-hub.png` (nuevo hub), `03-vf.png` con el selector, `07-feedback.png`, `08-resumen.png` con carrusel, `10-pendientes.png`.
