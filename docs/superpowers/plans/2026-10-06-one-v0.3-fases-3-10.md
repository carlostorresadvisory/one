# ONE v0.3 · Fases 3-10 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convertir ONE en cinco modos + Tienda alrededor de la esfinge (fases 3-10 de la spec §13), publicando cada fase por separado.

**Architecture:** Igual que fases 1-2: módulos ES en la raíz; cada modo = un módulo **puro** (`ordago.js`, `contrarreloj.js`, `masomenos.js`; `node --test`) + un módulo de **pantalla** (`*-ui.js`) que recibe sus dependencias inyectadas desde `app.js` (que solo enruta). Persistencia en `localStorage` con claves `one.*` incluidas en el respaldo v3. Herramientas de datos en `tools/` (`node --env-file=.env`).

**Tech Stack:** JS ES modules sin bundler, `node --test`, Playwright (e2e), ZzFX, canvas-confetti, WebGL (avatar), Wikidata SPARQL, OpenRouter/Groq (cascada gratis), Cloudflare Workers AI (FLUX schnell), Pillow/ffmpeg en local para recursos.

**Spec:** `docs/superpowers/specs/2026-10-05-one-v0.3-tres-modos-design.md` (aprobada el 6-oct; actualizada dos veces el 10-oct: fotos de fondo, Afinar a escala con fotos, suelo de nivel 3, resplandores solo dorados, esfinge v2 y «ONE abre directamente en el hub»; este plan está alineado con esa versión). Ejecutores: leer la spec entera antes de la primera tarea de cada fase.

## Cómo se ejecuta este plan

- **Una rama por fase, cada una sale de la anterior**: `v0.3-fase-3` salió de `diseno-secciones`; `v0.3-fase-4` sale de `v0.3-fase-3`, `v0.3-fase-5` de la 4, … Commit por tarea; al cerrar la fase, revisión final. **La publicación se hace cuando Carlos da el OK** (publicar la fase N publica también las anteriores aún sin publicar): **⚠️ Carlos** lanza `! git checkout main && git merge --ff-only v0.3-fase-N && git push origin main`. Después: `gh run list --limit 3` y `curl -s https://carlostorresadvisory.github.io/one/sw.js | head -5` debe mostrar la caché nueva.
- Cada fase termina en una tarea **«Cierre de fase»** (el «cierre común» al que remiten las demás fases) con la misma lista: suites en verde, e2e de no-scroll a 375×812 y 375×667, sube `CACHE` en `sw.js`, revisión final con Opus **ejecutando la app** + adversarial OpenRouter gratis (`delegar.mjs --escalera revisar`), actualizar `docs/PROXIMA-SESION.md` (LEAN: reescribir, no añadir).
- Verificación base: `node --test tests/*.test.js` (743 el 10-oct, al cerrar la fase 3) y `npx playwright test` (157 el 10-oct); cada fase sube el recuento y ninguna tarea baja el de la anterior. La suite e2e regenera `docs/capturas/*.png`: **no se commitean** (`git checkout -- docs/capturas` antes de cada commit).
- **Fase 3 hecha (pendiente de publicar). Orden: 4 → 5 → 6 → 7 → 8 → 9 → 10.** La 7 (imágenes) y la 8 (cifras) dependen de tareas de datos largas que se delegan con `delegar.mjs` cuando sean 🟢.
- Antes de cada fase, el controlador relee el código real que toca la fase. Este plan nombra el código por **función, módulo o `data-test`**, nunca por número de línea.
- **No existe la pantalla de inicio 🧠/💪 ni «Comenzar»** (fase 3, tareas 3.3 y 3.4b): ONE abre en el hub. Todo e2e empieza con `page.goto('/?ejemplo=1&test=1')` (ya en el hub) y entra a un modo con el helper `entrarEnModo(page, id)` (un clic en `[data-test="modo-<id>"]`); ningún paso depende de `cerebro`, `cuerpo` ni `comenzar`.
- Las marcas **⚠️ Carlos** señalan lo que solo puede hacer él (claves, VPS, decisiones de la spec §14, OK de publicación y prueba en el iPhone); si un paso no la lleva, lo hace el agente. Las marcas **🔶 Provisional** señalan una decisión que la spec deja abierta: se eligió la opción más simple para poder avanzar y Carlos puede cambiarla (lista completa al final).

## Global Constraints

- Paleta oscura + cian; **sin magenta**; dorado solo como acento (avatar, PREMIUM, pregunta dorada). **Resplandores solo en lo dorado** (pregunta dorada, objeto épico del cofre, esfinge del «¡Nuevo máximo!»): el avatar no lleva halo cian y nada más brilla (botones, comodines, cofres común y raro, fichas van planos).
- **Pantalla de pregunta con foto** (Órdago, Contrarreloj, Afinar con fechas): la foto es la protagonista y el enunciado va encima (`foto-pregunta.js`, fase 5); **ninguna tarjeta grande con emoji** (solo el icono del objeto ganado y los iconos de los objetos). Clásico y Repaso conservan su maquetación.
- **Dificultad:** Órdago y Contrarreloj solo sirven preguntas de **nivel 3-5** (`esJugableDificil`, fase 5); Comparar no empareja cifras con razón > ×4 ni fechas a más de 300 años; Clásico y Repaso siguen desde el nivel 1.
- **Ninguna pantalla hace scroll** y **la letra no se encoge** para encajar: se comprueba en **375×812 y 375×667** en cada pantalla nueva.
- Con el almacenamiento bloqueado **nada lanza**: cada `cargarX/guardarX` resuelve `almacen ?? globalThis.localStorage` **dentro** del `try` (patrón de `modos.js`).
- Imágenes: licencia libre con atribución; IA **solo como último recurso**; si una imagen no carga, color del área sin emoji grande — **nunca un hueco**; ninguna tarjeta grande con emoji (salvo el icono del premio).
- IA de imágenes: Cloudflare `@cf/black-forest-labs/flux-1-schnell` → Runware solo si Cloudflare agota; **cupo propio ≤ 100 imágenes IA/día**; pago dentro del tope **0,10 €/día**.
- Toda respuesta a una pregunta del banco pasa por `registrarRespuesta` (motor.js). Las cifras de Más o menos **no** tocan el radar.
- Premio en Clásico solo con 10/10; Repaso **nunca** da premio; Órdago **no da objetos** (su premio es el fondo, canjeable en la Tienda).
- Avatar (esfinge v2): `crearAvatar(...)` → `gesto(nombre)` sobre un reposo en bucle con respaldo de imagen fija; **un solo reproductor por pantalla** (en el hub solo en la tarjeta Tienda, sin avatar en la cabecera del hub); vídeos `muted` + `playsinline`; si falla, WebP fijo; en partida ≤ 120 px de alto (provisional 100 px; ⚠️ Carlos decide con las fotos montadas, spec §14); con `prefers-reduced-motion`, imagen fija.
- Ningún efecto altera la maquetación ni provoca scroll (todo superpuesto).
- Caché del service worker ≤ ~5 MB en total (clips del avatar incluidos: ≈ 4,95 MB al cerrar la fase 4; test en `tests/sw.test.js`).
- Código, comentarios, commits y textos en español; identificadores en español como el resto del repo.
- Sin dependencias nuevas en la app (cliente). En `tools/` y `servidor/` se permite `sharp` solo para la fase 7 (ver Tarea 7.3).

Hipótesis a **comprobar, no dar por buenas** (spec §7):
- H1: `desbloquear()` llama a `resume()` en `pointerdown`, que iOS **no** cuenta como activación de usuario para audio (sí `touchend`/`click`); la promesa se rechaza en silencio y el contexto sigue `suspended` cuando suena el «ding».
- H2: zzfx (import perezoso) llega **después** del primer gesto: `desbloquear()` devuelve `false` porque no hay motor y el «ding» de esa primera respuesta no suena.
- H3: el interruptor físico de silencio silencia Web Audio (en iOS ≥ 16.4 se evita con `navigator.audioSession.type = 'playback'`).
- H4: `reproducir()` programa el sonido sobre un contexto aún `suspended` (el `resume()` aún no ha resuelto) y se pierde.

```js
// ONE · depurar-sonido.js — panel de diagnóstico del audio en iOS (?depurar=sonido). No se precachea.
export function montarPanelSonido(sonido, documento = document) {
  const panel = documento.createElement('pre');
  panel.style.cssText = 'position:fixed;left:0;right:0;bottom:0;max-height:40vh;overflow:auto;margin:0;padding:8px;font:11px monospace;background:#000c;color:#4cc9f0;z-index:9999;white-space:pre-wrap';
  const boton = documento.createElement('button');
  boton.textContent = 'Probar ding';
  boton.style.cssText = 'position:fixed;right:8px;bottom:42vh;z-index:9999';
  boton.addEventListener('click', () => { sonido.desbloquear('click-panel'); sonido.reproducir('ding'); });
  const pintar = () => {
    const d = sonido.diagnostico();
    panel.textContent = JSON.stringify({ ...d, ua: navigator.userAgent, standalone: navigator.standalone === true }, null, 1);
  };
  documento.body.append(panel, boton);
  setInterval(pintar, 500);
  pintar();
}
```

- H2 → `precargar()` se lanza al cargar el módulo de la app **y** `desbloquear()` sin motor guarda `pendienteDesbloqueo = true`; cuando el motor llega y hay un gesto en curso (≤ 1 s), se reintenta en el siguiente gesto (no se puede fuera de gesto).
- H3 → en `precargar()`, si `navigator.audioSession` existe, `navigator.audioSession.type = 'playback'` (dentro de `try`).
- H4 → `reproducir()` con contexto no `running`: `contexto.resume().then(() => motor.zzfx(...))`.
- Review Focus 1 → al `visibilitychange` a visible, si el contexto no está `running`, volver a poner los oyentes de desbloqueo.
