# ONE v0.2b4 — Plan: generación que se entiende (tanda recordada, indicador, velocidad)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que una tanda pedida desde el Átomo no se pierda nunca (aunque iOS recargue la PWA), que el jugador vea SIEMPRE cuánto falta y dónde tocar para jugarla, que el chip de preguntas nuevas lleve a ellas, y que una tanda de 5 baje de 100 s a menos de 40 s sin gastar un céntimo.

**Architecture:** (T1) módulo nuevo `tanda.js` — persistencia de la tanda en curso en `localStorage` (`one.atomoTrabajo`) + cálculo PURO del tiempo restante, con tests propios sin DOM; el indicador fijo (`data-test="indicador-tanda"`) es DOM y vive en `app.js`, que lo alimenta desde el sondeo de `consultarTrabajo` y lo reanuda al arrancar. (T2) `app.js` guarda los ids de la última sincronización para que el chip `nuevas-servidor` arranque partida, el botón de área pasa a "+" y `atomo.js` renombra el nodo "Más…" a "Regenerar temas". (T3) servidor: `tools/visualizar.js` estrena las cascadas de Gemini gratis, el prompt pide la explicación de 25 a 40 palabras y `resolverPregunta` deja de reescribirla cuando ya cumple (solo pide el visual); `servidor/cola.js` mide segundos por pregunta con una media móvil de 5 tandas, la expone en `/generar` y `/trabajo/:id`, y conserva los terminados ≥ 1 h. (T4) e2e de recarga a mitad de tanda, capturas y README.

**Tech Stack:** PWA vanilla (ES modules, sin dependencias), Node 22, `node:test` con `fetchImpl`/`llamar`/`localStorage`/`reloj` falsos, Playwright con `page.route` a 375×812 y 393×852.

```js
// ONE · tanda.js — estado de la tanda de generación en curso (spec v0.2b4 §1 y §2). Mismo criterio
// de extracción que mazo.js/atomo.js: lo que se puede probar sin DOM ni red vive aquí, con sus
// propios tests (tests/tanda.test.js); el indicador (DOM) se queda en app.js.
//
// Por qué existe: `atomoTrabajoId` vivía SOLO en memoria (app.js:179). iOS recarga la PWA al
// cambiar de app o bloquear el móvil, así que la app olvidaba la tanda, dejaba de sondear y el
// aviso "Tanda lista" no llegaba nunca (diagnóstico de la spec §0, visto por Carlos el 15-sep 09:52).

export const CLAVE_TANDA = 'one.atomoTrabajo';

// Estimación mientras el servidor no ha hecho ni una pregunta de esta tanda y todavía no ha
// mandado su propio `segundosPorPregunta` (Tarea 3): misma cifra de arranque que usa el servidor.
export const SEG_POR_PREGUNTA_DEFECTO = 20;

/**
 * Segundos que faltan (spec §2): con >= 1 pregunta hecha, el ritmo REAL medido
 * ((ahora - inicio) / hechas) x las que faltan; con 0 hechas, la estimación del servidor
 * (`segundosPorPregunta`, o SEG_POR_PREGUNTA_DEFECTO). `null` cuando los datos no dan para nada
 * (nunca NaN: el indicador nunca debe pintar "~NaN s").
 */
export function calcularRestanteSeg({ inicio, ahora, hechas, pedidas, segundosPorPregunta } = {}) {
  if (!Number.isFinite(inicio) || !Number.isFinite(ahora)) return null;
  if (!Number.isInteger(pedidas) || pedidas <= 0) return null;
  const hechasValidas = Number.isInteger(hechas) && hechas > 0 ? Math.min(hechas, pedidas) : 0;
  const faltan = pedidas - hechasValidas;
  if (faltan <= 0) return 0;
  const transcurridoSeg = (ahora - inicio) / 1000;
  if (hechasValidas >= 1 && transcurridoSeg > 0) {
    return Math.max(1, Math.round((transcurridoSeg / hechasValidas) * faltan));
  }
  const porPregunta =
    Number.isFinite(segundosPorPregunta) && segundosPorPregunta > 0
      ? segundosPorPregunta
      : SEG_POR_PREGUNTA_DEFECTO;
  return Math.max(1, Math.round(porPregunta * faltan));
}

/** "~40 s" por debajo del minuto (decenas, de 10 a 50 — "~60 s" sería un minuto mal escrito) y
 * "~2 min" a partir de 60 s. Cadena vacía cuando no hay nada que decir (spec §2: redondeo). */
export function formatearRestante(seg) {
  if (!Number.isFinite(seg) || seg <= 0) return '';
  if (seg < 60) return `~${Math.min(50, Math.max(10, Math.round(seg / 10) * 10))} s`;
  return `~${Math.max(1, Math.round(seg / 60))} min`;
}
```

```js
function esTextoNoVacio(v) {
  return typeof v === 'string' && v.trim().length > 0;
}

function esTandaValida(datos) {
  if (!datos || typeof datos !== 'object') return false;
  if (!esTextoNoVacio(datos.id) || !esTextoNoVacio(datos.corto)) return false;
  return Number.isFinite(datos.inicio) && Number.isInteger(datos.pedidas) && datos.pedidas > 0;
}

/** Tanda guardada, o null si no hay ninguna. Una clave corrupta (JSON roto, campos ausentes) se
 * trata como "no hay tanda": nunca lanza, misma política que cargarEstado en app.js. */
export function leerTanda() {
  try {
    const crudo = localStorage.getItem(CLAVE_TANDA);
    if (!crudo) return null;
    const datos = JSON.parse(crudo);
    if (!esTandaValida(datos)) return null;
    return { id: datos.id, corto: datos.corto, inicio: datos.inicio, pedidas: datos.pedidas };
  } catch {
    return null;
  }
}

/** Guarda la tanda en curso. `false` si los datos no valen o si localStorage no admite escritura
 * (llena, modo privado): la sesión sigue funcionando en memoria, igual que guardarEstado. */
export function guardarTanda({ id, corto, inicio, pedidas } = {}) {
  if (!esTandaValida({ id, corto, inicio, pedidas })) return false;
  try {
    localStorage.setItem(CLAVE_TANDA, JSON.stringify({ id, corto, inicio, pedidas }));
    return true;
  } catch {
    return false;
  }
}

/** Se llama en estado terminal (tras mostrar "Tanda lista" o el fallo) y en 404 (spec §1). */
export function borrarTanda() {
  try {
    localStorage.removeItem(CLAVE_TANDA);
  } catch {
    // Si ni borrar se puede, leerTanda la volverá a ver en la próxima apertura y el sondeo dará
    // 404 -> "La tanda se perdió, genera otra". No hay nada mejor que hacer aquí.
  }
}
```

### Contradicciones código-vs-spec encontradas (gana el código)

1. **El "salto del acortado" no está donde la spec dice.** §6b lo pide en `resolverPregunta`, pero el bucle de acortado vive en `tools/visualizar.js#generarVisualYExplicacion` (`INTENTOS_EXPLICACION = 3`, líneas 465-510) y **ya** corta al primer intento cuando la propuesta tiene ≤ 40 palabras (línea 496). En `resolverPregunta` lo único que se repite es el **visual** (líneas 656-680). *Resuelto en T3 Steps 11-15*: se añade un salto REAL y opt-in (`saltarAcortado`) que, cuando la explicación de entrada ya cumple, ni siquiera pide reescribirla — solo el visual.
2. **La spec apunta al fichero de prompts equivocado.** §6b señala `tools/prompts-preguntas.js`, pero el prompt que reescribe explicaciones es `tools/visualizar.js#promptSistemaGenerador` (línea 315, "LÍMITE DURO de 40 palabras"); `prompts-preguntas.js` solo dice "1-3 frases", sin ningún límite de palabras (líneas 36-40). *Resuelto*: se cambian los dos (uno para que la explicación nazca ya con el límite, otro para que la reescritura lo respete).
3. **`terminados` no tiene retención por tiempo.** §1 dice "conserva los trabajos terminados al menos 1 h", pero `servidor/cola.js` es un `Map` con tope de 100 entradas (línea 20) que tira la más antigua (líneas 158-165): con tráfico alto un trabajo podía desaparecer en minutos. *Resuelto en T3 Step 25* con `terminadoEn` + `RETENCION_TERMINADOS_MS`, y `TERMINADOS_MAX` subido a 500 como tope duro.
4. **El chip que se elimina tiene un segundo consumidor.** §2 dice que el indicador "sustituye al chip", pero `app.js` lo usa también para el **chip adelantado** (`UMBRAL_ANTICIPADO_ATOMO`, líneas 1118-1124): "Tanda lista: N" MIENTRAS el trabajo sigue corriendo — incompatible con un indicador que a la vez dice "5 de 10 · ~1 min". *Resuelto en T1*: se conserva la fusión adelantada al banco (las preguntas entran antes) y se elimina el anuncio adelantado; los ids se guardan en `atomoTandaLista` por si salta el tope de 120 sondeos y hay que ofrecer algo jugable.
5. **Hay tres textos de fallo, no uno.** §2 solo contempla "No se pudo generar" 6 s, pero el código tiene además "El servidor tarda demasiado, prueba más tarde" (tope de sondeos, línea 1129) y usa el mismo chip para el 404, al que la spec §1 da su propio texto. *Resuelto en T1*: tres textos distintos ("No se pudo generar", "La tanda se perdió, genera otra", "El servidor tarda demasiado"), todos por `mostrarIndicadorTandaFallida` con los mismos 6 s.
6. **`encolar` no sabe contar preguntas.** §6c pide `estimadoSeg` = media × (preguntas por delante + pedidas), pero `cola.encolar` devuelve `{trabajoId, posicion}` donde `posicion` cuenta **trabajos** (línea 142-150) y `estadisticas()` no tiene ningún contador de preguntas pendientes. *Resuelto en T3 Step 18*: `encolar` devuelve además `preguntasPorDelante` y `pedidas`.
7. **El botón de área ya no será literalmente "un círculo de 44 px".** §4 pide "círculo, mismo tamaño táctil 44 px"; el código tiene un `<span role="button">` de 24 px visibles con un `::before` de `inset: -10px` que da 44 px de toque real (estilos.css 1976-1999), y su `aria-label` actual es "Elegir subtema de <área>" (app.js 3304), no el de la spec. *Resuelto en T2 Steps 6-10*: se conserva el mecanismo (que ya cumple el tamaño táctil y no tapa la tarjeta) y se cambian solo el glyph y el `aria-label`.
8. **Eliminar el chip rompe cuatro aserciones e2e existentes.** `tests/e2e.spec.js` afirma contra `[data-test="tanda-lista"]` en las líneas 3081, 3134 y 3174, y contra el texto exacto de `nuevas-servidor` en la 2764. La constraint habitual de este proyecto ("tests previos sin tocar aserciones") no se puede cumplir aquí. *Resuelto*: se declara como única excepción en Global Constraints y las cuatro se reescriben en T1 Step 11 y T2 Step 1.
9. **"4 de 10" no es alcanzable con el contrato real del servidor.** §2 usa "4 de 10" como ejemplo, pero `trabajo.hechas` avanza de lote en lote (`trabajo.hechas += tamanoLote` con `TAMANO_LOTE = 5`, `servidor/cola.js` 15 y 290): con `pedidas: 10` el indicador solo puede mostrar 0, 5 y 10. *Resuelto en T1*: se conserva la fórmula y se pinta el `hechas` real; el ritmo medido entra en juego al cerrar el primer lote, y hasta entonces manda `segundosPorPregunta` del servidor. Si Carlos quiere ver el progreso pregunta a pregunta, eso es bajar `TAMANO_LOTE` en el servidor — decisión de producto, **fuera de alcance de esta versión**.
