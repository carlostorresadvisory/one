# ONE v0 · plan de implementación

> **Para agentes ejecutores:** cada tarea la implementa un subagente distinto con la spec y esta tarea delante. TDD donde hay lógica (motor, validación, pipeline). **No commitear**: el orquestador commitea al cerrar cada fase. Los pasos usan `- [ ]`.

**Objetivo:** PWA instalable en el iPhone de Carlos: pulsa JUGAR, 10 preguntas sin teclado (4 mecánicas), racha, nivel por área, repaso Leitner, banco de 200 preguntas verificadas por un segundo modelo gratis.

**Arquitectura:** tres unidades independientes que se encuentran al final — `motor.js` (lógica pura, testeada en Node), `app.js` + estáticos (UI/PWA, consume el motor y un JSON), `tools/` (pipeline Node que produce `datos/banco.json` con OpenRouter). Estado en localStorage. Publicación estática en GitHub Pages.

**Stack:** Node 24 (`node --test`, `fetch` nativo, `zlib`), HTML/CSS/JS vanilla con módulos ES, Playwright (única dependencia de desarrollo), OpenRouter API (solo modelos `:free`).

**Spec:** `docs/superpowers/specs/2026-09-12-one-v0-design.md` — leerla entera antes de empezar cualquier tarea.

## Restricciones globales

- Cero dependencias en tiempo de ejecución. Única dependencia de desarrollo: `@playwright/test`.
- Todo en español: código (nombres, comentarios), textos de UI, commits.
- **Rutas relativas** en `index.html`, `manifest.json`, `sw.js` y `fetch` (la app se sirve en `https://<usuario>.github.io/one/`, no en la raíz). Nunca `/datos/...`; siempre `datos/...` o `./datos/...`.
- `OPENROUTER_API_KEY` solo desde `process.env`. Nunca en ficheros, logs ni salida. `.gitignore` excluye `datos/llamadas.log`, `datos/borradores/`, `node_modules/`, `test-results/`.
- Solo modelos cuyo id termina en `:free`. `tools/openrouter.js` **rechaza** cualquier otro id salvo flag explícito `--permitir-pago` (que hoy nadie pasa). Presupuesto: 0 €.
- Móvil primero: 375×812. Tap targets ≥ 44 px. `motor.js` no toca `window`, `document` ni `localStorage`.
- Fechas siempre como `'YYYY-MM-DD'` (string), sin `Date` en el motor salvo en `sumarDias`.

## Contratos (los ven todas las tareas)

### Pregunta (`datos/banco.json`, array)
```js
// comunes
{ id: 'eco-007', area: 'economia', tipo: 'vf'|'test4'|'ordenar'|'error', nivel: 1..5,
  enunciado: 'string', explicacion: 'string', confianza: 0..1,
  generador: 'id modelo', verificador: 'id modelo', verificado: true }
// vf:      respuesta: true|false
// test4:   opciones: [s,s,s,s], correcta: 0..3
// ordenar: criterio: 'de menor a mayor …', items: [s,s,s,s]   // orden correcto; la UI baraja
// error:   tarjeta: { titulo: 's', filas: [{etiqueta:'s', valor:'s'}, …3..5] }, sospechoso: índice
```
Prefijos de id por área: `eco, his, cie, tec, geo, fil, art, log`.

### `motor.js` (módulo ES, exports con nombre)
```js
export const AREAS = ['economia','historia','ciencia','tecnologia','geografia','filosofia','arte','logica'];
export const XP_BASE = { vf: 5, test4: 8, ordenar: 12, error: 12 };
export const INTERVALOS = [1, 3, 7, 14, 30];          // días de espera según la caja 0..4
export const MEZCLA = { vf: 3, test4: 4, ordenar: 2, error: 1 };  // objetivo por partida de 10
export function sumarDias(fecha, n)                   // 'YYYY-MM-DD' → 'YYYY-MM-DD'
export function crearEstado(hoy)                      // → estado (ver spec §4), combo: 0
export function evaluar(pregunta, respuesta)          // → boolean
//   vf: respuesta boolean · test4: índice · ordenar: array de índices originales en el orden elegido (correcto = [0,1,2,3]) · error: índice
export function seleccionarPartida(estado, banco, hoy, n = 10, rng = Math.random) // → array de ids
export function registrarRespuesta(estado, pregunta, correcta, hoy) // → { estado, delta: { xp, combo, correcta } }
export function actualizarRacha(estado, hoy)          // al terminar la partida → estado (racha, combo a 0)
export function resumenProgreso(estado, banco)        // → { racha, xp, hoy: {respondidas, aciertos}, porArea: [{ area, nivel, aciertoReciente: 0..1|null, estables, total }] }
export function exportar(estado)                      // → string JSON
export function importar(json)                        // → estado; lanza Error si version ≠ 1 o falta estructura
```
Reglas (copiadas de la spec, exactas):
- **Leitner**: acierto → `caja = min(caja+1, 4)`, `proximo = sumarDias(hoy, INTERVALOS[caja])`; fallo → `caja = 0`, `proximo = sumarDias(hoy, 1)`. Tarjeta nueva nace en la primera respuesta.
- **Nivel por área** (1..5): `seguidosOk` cuenta solo aciertos de tipo ≠ `vf`; al llegar a 3 → nivel+1 y `seguidosOk = 0`. Cualquier fallo → `seguidosOk = 0`, `seguidosKo+1`; al llegar a 2 → nivel−1 y `seguidosKo = 0`. Cualquier acierto → `seguidosKo = 0`. Acierto `vf` no toca `seguidosOk`.
- **XP**: `Math.round(XP_BASE[tipo] × (1 + 0.1 × nivel) × (combo ≥ 3 ? 1.5 : 1))`, donde `combo` es el valor **tras** contar esta respuesta. Fallo → 0 XP, `combo = 0`.
- **Selección**: repasos = tarjetas con `proximo ≤ hoy`, no reportadas, ordenadas por `proximo` ascendente, máximo `Math.round(0.3 × n)`. Nuevas = preguntas sin tarjeta, no reportadas, `nivel === areas[area].nivel` (si no hay, ±1; si no, cualquiera). Se cubre `MEZCLA` como objetivo blando (si falta un tipo, se rellena con otro). Rotación de áreas: no repetir área en dos posiciones consecutivas cuando haya alternativa. Si el banco no da para `n`, devuelve menos, nunca lanza.
- **Racha**: `actualizarRacha`: si `ultimaFecha === hoy` no cambia; si `ultimaFecha === sumarDias(hoy, -1)` → `dias+1`; en otro caso `dias = 1`. Fija `ultimaFecha = hoy`, `combo = 0`.
- **Hoy**: `registrarRespuesta` reinicia `hoy` si `estado.hoy.fecha !== hoy`. `ultimas` del área guarda las últimas 20 (bool). `historial` guarda las últimas 500.
- **Estables** = tarjetas del área con `caja ≥ 3`. `aciertoReciente` = media de `ultimas` o `null` si vacío.

### `app.js` ↔ `motor.js`
- Carga `datos/banco.json` (o `datos/banco.ejemplo.json` si `location.search` contiene `ejemplo=1`).
- Estado en `localStorage['one.estado']` vía `exportar`/`importar`; si no hay o falla → `crearEstado(hoy)`.
- `hoy` = fecha local del dispositivo en `'YYYY-MM-DD'`.
- Flujo: Inicio → `seleccionarPartida` → por cada id: pintar mecánica → `evaluar` → `registrarRespuesta` → guardar → feedback → siguiente → `actualizarRacha` → guardar → Resumen.
- Selectores estables para e2e (atributo `data-test`): `inicio`, `jugar`, `progreso`, `pregunta`, `opcion-0..3`, `vf-verdadero`, `vf-falso`, `item-0..3`, `fila-0..4`, `porque`, `esta-mal`, `siguiente`, `resumen`, `otra`, `racha`, `barra-<area>`, `exportar`.
