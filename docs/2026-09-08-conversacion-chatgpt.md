# 3. El motor de preguntas: adaptativo de verdad

Aquí está probablemente la parte más importante.

No basta con:

> Aciertas → pregunta más difícil  
> Fallas → pregunta más fácil

Eso es demasiado simplista.

El sistema debería mantener un modelo probabilístico de tu conocimiento.

Para cada concepto:

```text
Concepto: Teoría de Juegos

Conocimiento estimado: 82%
Confianza: Alta
Última interacción: hace 12 días
Probabilidad de olvido: 18%
Capacidad de transferencia: 65%
Profundidad conceptual: 78%
```

Y distinguir entre diferentes tipos de conocimiento.

### Saber algo no es binario

Puedes:

| Dimensión | Ejemplo |
|---|---|
| Reconocer | "Sé qué es Nash Equilibrium" |
| Explicar | "Puedo explicarlo" |
| Aplicar | "Puedo resolver un problema" |
| Transferir | "Puedo usarlo en biología" |
| Criticar | "Sé cuándo no funciona" |
| Crear | "Puedo generar un modelo nuevo" |

La dificultad debería subir verticalmente.

Por ejemplo:

### Nivel 1
> ¿Qué es un equilibrio de Nash?

### Nivel 2
> Encuentra el equilibrio.

### Nivel 3
> ¿Qué ocurriría si cambiamos esta condición?

### Nivel 4
> ¿Por qué este modelo falla en mercados reales?

### Nivel 5
> Diseña un mecanismo alternativo.

### Nivel 6
> Relaciónalo con evolución biológica.

Aquí es donde empieza el aprendizaje universitario real.


## ChatGPT · spec «ONE» (documento)

# ONE
### The infinite game for learning everything

## 1. Visión

ONE es una aplicación móvil de aprendizaje continuo que convierte el conocimiento en un videojuego adaptativo.

El usuario no estudia cursos, no lee libros dentro de la aplicación y no rellena ejercicios escritos.

Simplemente abre la aplicación y pulsa:

# JUGAR

La aplicación genera automáticamente una secuencia de desafíos intelectuales adaptados al conocimiento, errores, intereses, memoria y nivel del usuario.

Todas las respuestas se realizan mediante:

- tap
- swipe
- drag & drop
- selección múltiple
- sliders
- ordenar elementos
- conectar elementos
- elegir entre escenarios
- controles visuales

Nunca se requiere teclado ni micrófono.

---

# 2. Objetivo

El objetivo no es maximizar contenidos completados.

El objetivo es maximizar:

**conocimiento + comprensión + retención + razonamiento + conexiones interdisciplinarias + pensamiento crítico.**

El sistema debe intentar convertir el aprendizaje en un hábito espontáneo:

> Abrir → jugar 5 minutos → pensar → aprender → cerrar.

Si el usuario quiere continuar:

> Seguir jugando.

---

# 3. Principios de diseño

## P1 — Cero fricción

Desde abrir la aplicación hasta la primera pregunta:

**máximo 2 taps.**

---

## P2 — Nunca preguntar qué estudiar

El usuario no debe decidir diariamente qué materia estudiar.

La IA decide qué desafío tiene mayor valor esperado.

---

## P3 — Cero escritura

Todas las preguntas deben poder responderse mediante interacción visual.

---

## P4 — Microlearning

Una interacción debe durar aproximadamente:

**5–30 segundos.**

Una sesión normal:

**5–10 minutos.**

Una sesión larga:

**15–30 minutos.**

---

## P5 — Dificultad adaptativa

El sistema debe buscar constantemente el límite superior de la capacidad del usuario.

No:

> fácil → fácil → fácil

Ni:

> imposible → frustración.

Sino:

> suficientemente difícil para obligar a pensar, suficientemente fácil para querer continuar.

---

## P6 — Explicaciones bajo demanda

Nunca mostrar automáticamente una explicación larga.

Después de responder:

> ✓ Correcto

y opcionalmente:

**¿Por qué?**

Si pulsa:

> mostrar explicación breve.

Y después:

> Profundizar

para recibir una explicación más avanzada.

MIND & BODY no pretende crear:

Pretende crear:
